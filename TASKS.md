## Done

- [x] **Ported `EnsureDefaultRolesExistAsync` startup role-seeding from ludemia (2026-09-09)** — `DefaultRoleCatalog.Roles` was read only by `RoleManagementRepository.RestoreDefaultRolesAsync()` (reachable only via `POST api/admin/roles/restore-defaults`); the `Program.cs` startup block seeded only `Admin`, so on a fresh database any grant of a catalog role (`UserManagementRole`, `PersonManagementRole`) threw `RoleNotFound` until an admin pressed that button. Added `IRoleManagementRepository.EnsureDefaultRolesExistAsync()` — creates only the *missing* catalog roles with their catalog claims, touching nothing that already exists — and call it from the `Program.cs` startup scope right after the `Admin` role is ensured. Deliberately not `RestoreDefaultRolesAsync()` (full reconcile, removes stray claims, would undo admin customisations every restart). hekucoreapp's `DefaultRoleCatalog` has no `ClaimlessRoles` (a ludemia-only concept), so the port is just the `Roles` loop. Build clean; no migration (Identity data, not schema). This was the last outstanding ludemia→core port.
- [x] **Validate email during registration (2026-09-09)** — added an admin-configurable **"require email confirmation"** toggle plus the full verify flow. New generic `AppSettings` singleton infrastructure (entity `app_settings` Id=1, `AppSettingsPermission {Read,Update}` in `PermissionCatalog`, service/repository/DTOs, `AppSettingsSeeder`, `GET/PUT api/admin/app-settings`, `admin/settings` Angular page) — mirrors the multi-tenant cores' `MultiTenantSettings` pattern, which hekucoreapp lacked. When the toggle is **off** (default) accounts are created `EmailConfirmed = true` and nothing changes; when **on**, `AuthService.RegisterAsync` creates the user unconfirmed, emails a `/confirm-email?userId=&token=` link (new `EmailTemplates.ConfirmEmail`, `App:FrontendBaseUrl` config with request-origin fallback), issues no token, and `LoginAsync` hard-blocks unconfirmed users (after the password check, so it's not an email oracle). New `POST api/auth/confirm-email` + `POST api/auth/resend-confirmation` (always 200). Google OAuth is unaffected and now also confirms a pre-existing unconfirmed account on link. Admin-provisioned users (`UserManagementRepository`) are created confirmed. Migration `AddAppSettings` creates the table and **grandfathers every existing account** (`UPDATE "AspNetUsers" SET email_confirmed = true`), so turning the toggle on later only gates new registrations. Frontend: `confirm-email` dual-mode page (auto-confirm from link params / "check your inbox" + resend), `register` redirects there, `login` surfaces a resend link on failure, i18n en+es. **Verified:** `dotnet build` + `ng build` clean; migration created and `has-pending-model-changes` reports none. **Not browser-verified** — hekucoreapp's Supabase DB is unreachable (project reaped). Ported to ludemia, gestamind and hekutenantcoreapp the same day (gestamind's migration applied to its live DB).
