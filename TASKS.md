- [x] **Auto-create the bootstrap admin on a fresh/empty database (2026-09-10)** — provisioning a new DB used to be a two-step manual dance: self-register through the running app *first*, then restart so the `Program.cs` startup block promotes that now-existing user. Startup only ever *granted a role to a user that already existed* — never created one — so a fresh DB had no first way in, and "I set `BootstrapAdminEmail` but can't log in" was a predictable footgun (hit again in the 2026-09-09 DB-recreation session). Now, in the startup scope, when `BootstrapAdminEmail` is set **and `AspNetUsers` is entirely empty** (`!await userManager.Users.AnyAsync()` — guard on *empty table*, never merely "no active admin", so it can never fire on an established install), the block creates that user (`EmailConfirmed = true`, `MustChangePassword = true`, `IsActive = true`, `UserName = email`) and the existing promotion path picks it up in the **same** pass — hekucoreapp grants `Admin`; hekutenantcoreapp grants `SuperAdmin` + default-tenant membership + tenant-scoped `Admin`. Password: new optional `BootstrapAdminPassword` config key (blank default in `appsettings.json`, set via user-secrets) — if unset, a random 20-char CSPRNG password (`RandomNumberGenerator.GetString` over an unambiguous alphabet + `Aa1!` to clear the Identity complexity rules) is generated and logged **once** at `Warning`. `userManager.CreateAsync` failure logs at `Warning` and falls through — startup never crashes on it. hekucoreapp block sits right after `EnsureDefaultRolesExistAsync()`; hekutenantcoreapp block sits just before the existing `bootstrapUser` lookup so the create flows straight into the SuperAdmin/default-tenant wiring. No migration (Identity data, not schema). **Verified:** `dotnet build` clean in both cores (pre-existing `UserRepository.cs` CS8619 warning unchanged); hekutenantcoreapp `dotnet test` 54/54 green; both APIs boot cleanly against their live DBs — the new `AnyAsync` guard runs and correctly skips the create block (both DBs already have users), so the happy path (empty DB) is reasoned-through, not browser-verified.
